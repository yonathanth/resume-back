# Deploying for testing: Vercel (frontend) + Render (API)

The browser only ever talks to the Vercel site. The frontend forwards
`/api/v1/*` to the API on Render (a rewrite in `resume-front/next.config.ts`),
so the sign-in cookie is first-party — browsers block third-party cookies —
and CORS never comes into play.

```
browser ──► https://<app>.vercel.app ──/api/v1/*──► https://gomoxie-api.onrender.com
                                                     (Polar / Chapa webhooks go straight here)
```

## 1. API on Render

1. Push this repo to GitHub.
2. Render → **New → Blueprint** → pick the repo. It reads `render.yaml`
   (Docker, free plan, health check `/health`).
3. Fill in the values it asks for, from your `.env`:
   - `DATABASE_URL` — the Neon URL
   - `FRONTEND_URL` and `CORS_ORIGIN` — `https://<app>.vercel.app` (no trailing slash).
     You'll know it after step 2 below; put a placeholder and come back.
   - `GOOGLE_CALLBACK_URL` — `https://<app>.vercel.app/api/v1/auth/google/callback`
   - `CHAPA_RETURN_URL` — `https://<app>.vercel.app/payment/chapa/return`
   - `POLAR_CHECKOUT_RETURN_URL` — `https://<app>.vercel.app/payment/polar/return`
   - `CHAPA_WEBHOOK_URL` — `https://gomoxie-api.onrender.com/api/v1/payments/webhook/chapa`
   - the AI, email, Google, Chapa, Polar and push keys (leave unused ones empty)
4. Deploy. Every start runs `prisma migrate deploy` (applies new migrations,
   never resets anything), then the server.

`JWT_ACCESS_SECRET` is generated by Render. The settings in `render.yaml` that
aren't secrets (`TRUST_PROXY`, `MAX_CONCURRENT_RENDERS=1`,
`REFRESH_COOKIE_SAMESITE=lax`, `CHROME_NO_SANDBOX` in the Dockerfile) are
already set.

## 2. Frontend on Vercel

1. Vercel → **Add New → Project** → import the `resume-front` repo (framework: Next.js).
2. Environment variables:
   - `BACKEND_URL` = `https://gomoxie-api.onrender.com` — where `/api/v1` is forwarded
   - `NEXT_PUBLIC_API_URL` = `https://<app>.vercel.app` — the browser calls this site itself
   - `NEXT_PUBLIC_SITE_URL` = `https://<app>.vercel.app` — until gomoxie.app points here
     (canonical URLs, sitemap, share images)
   - `NEXT_PUBLIC_GOOGLE_CLIENT_ID` and any other `NEXT_PUBLIC_*` values from your local env
3. Deploy, then go back to Render and set `FRONTEND_URL` / `CORS_ORIGIN` /
   the callback and return URLs to the real Vercel address.

## 3. Outside services

- **Google Cloud Console** → the OAuth client → Authorized redirect URIs: add
  `https://<app>.vercel.app/api/v1/auth/google/callback`; Authorized JavaScript
  origins: add `https://<app>.vercel.app`.
- **Polar** → webhook endpoint `https://gomoxie-api.onrender.com/api/v1/webhooks/polar`
  (same secret as `POLAR_WEBHOOK_SECRET`).
- **Resend**: `EMAIL_FROM` must be on a domain verified in Resend
  (`onboarding@resend.dev` only delivers to your own address).

## What to expect on the free plan

- The API sleeps after ~15 minutes without traffic; the next request wakes it
  (30–60 s). The first page load after a quiet spell can fail or spin — reload.
- While it sleeps, background jobs (lifecycle emails, notification recovery)
  don't run.
- 512 MB of memory: PDFs render one at a time. If renders crash with
  out-of-memory errors, that's the limit — a paid instance fixes it.
- Vercel limits how long it waits for a proxied request. If long AI
  generations start failing through the proxy, check that limit first.

## Going live

Point `gomoxie.app` at Vercel (and optionally `api.gomoxie.app` at Render),
set `NEXT_PUBLIC_SITE_URL=https://gomoxie.app`, move the API to an always-on
instance, and update the URLs above.
